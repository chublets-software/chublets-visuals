# chublets-visuals

Presentation and paper graphics for [chublets.software](https://chublets.software)
— generated by pure-Python scripts, no external CLI tools required. Sibling
repository to [FDOx-squirrel/fdox-visuals](https://github.com/FDOx-squirrel/fdox-visuals),
same house pattern, own palette.

## What this is

```
data/raw/*.xlsx, *.csv   real source data (crosswalk, property lists), read at build time
data/raw/open-archaeo/    a vendored snapshot of github.com/n4o-rse/open-archaeo (py/wikidata/main.py)
      │
      ▼  py/step_*.py     geometry + text (no rendering logic)
      │
      ▼  main.py
img/<block>/*.svg         source, versioned, grouped by block
      │
      ▼  resvg-py (in-process, no rsvg-convert/ImageMagick/libcairo needed)
img/<block>/*.png         final graphics for slides, papers, READMEs — transparent background
```

Every graphic lives under a block subfolder, never directly in `img/`:

`badge` = the small transparent icon alone (for slide corners, navigation).
`detail` = the diagram that actually explains the step; every `detail`
diagram carries the same badge icon plus a "Step N — Title" header, so it
stays visibly tied to its badge (mirrors how `fdox-visuals` keeps its step
icon present everywhere, not just on the banner).

**Block 1 — CodeMeta / Wikidata / chublets datamodel:**

- **`chublets-codemeta-overview`** — the CodeMeta term set (`Thing` →
  `CreativeWork` → `SoftwareSourceCode`/`SoftwareApplication`) as a class
  diagram, built from `data/raw/codemeta-wikidata-crosswalk.xlsx`. Replaces
  a screenshot of the codemeta.github.io force-directed term graph, which
  cannot be re-rendered byte-identically.
- **`chublets-wikidata-properties-overview`** — the Wikidata
  WikiProject Informatics/Software/Properties set, grouped into five
  functional categories, from `data/raw/wikidata-software-properties.csv`.
- **`chublets-codemeta-wikidata-crosswalk`** — the same class tree as the
  CodeMeta overview, with every field tagged either with the Wikidata
  property it maps to, or as unmapped.
- **`chublets-wikibase-datamodel`** — the concept the other three build up
  to: the chublets Wikibase property set is the union of the reused
  Wikidata properties and new properties for the CodeMeta-only fields, read
  live from the other two steps' own sources.

**Block 3 — chublets.software four-step pattern** (Ingest → Model →
Curate & Link → Export & Publish): one banner, four icon badges, and four
detail diagrams that actually explain each step (three input sources for
Ingest, the same federated-datamodel numbers as Block 1 for Model, a
four-stage curation workflow for Curate & Link, and the SPARQL-to-
marketplace export pipeline for Export & Publish).

**Block 2 — the FAIR4RS chain** (Findable → Accessible → Interoperable →
Reusable): same banner-plus-badges-plus-detail structure as Block 3, own
icon set (magnifying glass, open padlock, linked rings, reuse arrow).
Three detail diagrams are explanatory cards; Interoperable gets an actual
hub diagram (CodeMeta in the centre, spokes to Wikidata/DCAT/DataCite/CFF)
because "interoperable" specifically means connecting several
vocabularies. Mechanisms are a proposal, not yet checked against the
deRSE26 paper's own FAIR table — see `PRIMER.md` Teil D.

**System architecture (S5, S6, S6b, S6c)** — `chublets-software-architecture`: the
five-stage bird's-eye view (Wikidata bridge → data sources → chublets
Wikibase → export pipeline → marketplaces) that consolidates Block 1 and
Block 3 into the single diagram that used to be three separate F28 panels.
Reads the same datamodel numbers as Block 1/Block 3, live, so it can't
drift from them. `open-archaeo-wikidata-pipeline` shows what `python
py/wikidata/main.py all` runs automatically (eight read-only steps),
parsed straight out of a vendored copy of the real `py/wikidata/main.py`
(`data/raw/open-archaeo/wikidata-main.py` + `py/open_archaeo_data.py`) —
refreshing it when the upstream repo changes is a file copy, not a
rewrite. `open-archaeo-two-routes`, `open-archaeo-python-route` and
`open-archaeo-openrefine-route` (from `github.com/n4o-rse/open-archaeo`
directly) cover the rest: the stratified two-team split, and the
interactive session for each route.

All planned work (Block 1, Block 2, S4, S4b, S4c, S5, S6, S6b, S6c, S7) is
built; see [`PRIMER.md`](PRIMER.md) Teil D for what's next.

**Talk-specific slide (S7)** — `chublets-talk-closing`: the eight badges
(four-step + FAIR4RS) as a ring around the chublets logo (`img/source/`),
composited the way `fdox-visuals` composites real assets onto a generated
canvas. A closing/summary slide, not a reusable generic badge.

## Usage

```cmd
pip install -r requirements.txt
python main.py
```

```cmd
python main.py --list                 show the steps
python main.py --only crosswalk       rebuild one graphic
python main.py --from crosswalk       this step and everything after
python main.py --skip datamodel       everything but this
python main.py --dry-run              print the plan, run nothing
python main.py --strict               warnings become errors (what CI would run)
```

Running it twice produces byte-identical output; `git status` stays clean
after the second run.

## Design

Colour and type live in one place, `py/visuals_utils.py` — every step
imports from there rather than repeating a hex code. `CHUBLETS_PURPLE`
(`#3B1F4A`) and `CHUBLETS_GOLD` (`#B8862E`) are sampled from the
chublets.software logo; a five-way `CATEGORY_COLORS` palette (purple, gold,
teal, rust, slate blue) covers grouped diagrams that need more than the two
house colours.

Typeface is [Fira Sans](https://github.com/mozilla/Fira) (Mozilla, SIL Open
Font License 1.1), vendored under `fonts/` — a fresh clone renders
identically without the font being installed on the machine that runs it.

Every PNG is cropped to its content plus an exact 10px transparent border,
and kept in the low single-digit megapixels — large enough to look sharp on
any screen, small enough to stay well under Google Slides' 25-megapixel
insert limit, which otherwise silently re-compresses (and visibly blurs)
anything larger.
